# 收纳路径安全迁移，方案二

日期：2026-09-29。范围为设置页和首次引导中的默认收纳路径迁移。

## 行为与边界

- 复制全部文件，读取源与目标所有文件数据流进行 SHA-256 校验，整批完成后才提交默认根目录与组件映射。
- 源文件始终保留。取消、异常、配置提交失败均不执行源文件删除或自动搬回。
- 移除“非空目标即上次完整副本”的判断及残留清理入口。首次使用已有目标子目录会拒绝操作，不覆盖、不合并、不送回收站。
- 设置页和首次引导使用同一个风险确认及进度对话框，默认按钮为取消。明确提示独立备份、全量目标空间、复制和校验耗时、持续供电、磁盘连接与解锁、禁止同时编辑、保留原文件和中断副本。
- 当前准入为可访问的本地 NTFS 卷，包括正常解锁的 BitLocker NTFS 卷。UNC、其他文件系统、重解析点、EFS 文件和目录上的附加数据流会明确拒绝，不以丢失特殊内容换取成功。
- 普通文件的 NTFS 附加数据流通过 Windows CopyFileEx 保留，并参与内容校验；文件只读属性与空目录同样保留。
- 真正的文件访问必须成功；不根据状态查询失败推断已经解锁。不会暂停 BitLocker、自动解锁或收集恢复密钥。转到未加密目标的保护变化在风险弹窗内说明。

## 代码责任

- ManagedStorageMigrationService 管扫描、空间预检、恢复记录、复制与校验，全部文件 IO 在后台执行。
- FileService.StorageCopy 管稳定读取、数据流散列与复制校验；Windows API 声明集中在 Platform/StorageMigrationNativeMethods。
- WidgetManager.StorageMigration 管组件操作状态、映射提交及启动时的中断提交协调。
- 设置页在迁移成功后只刷新路径展示，不再次排队写入默认路径。
- 保留普通文件拖拽/移动的既有实现；只替换默认收纳路径迁移链路。

## 恢复与空间

恢复记录位于应用数据目录的 managed-storage-migrations，采用 source-generated JSON 和原子保存。目标子目录记录卷与文件对象标识，重试时验证身份及源清单，避免盘符复用或目录替换被静默接受。

阶段为 Planned → Copying → Verifying → Verified → Committing → Committed。配置提交中断时，若两份配置已经一致指向新位置则补记完成；否则将仍属于该任务的映射恢复为未改动的原路径。目标未解锁时不会清空映射或删除文件。

已完成文件只有内容重新验证通过才能在重试中复用。当前不实现单个大文件的字节偏移续传；未完成的文件重新复制。部分副本留在目标 .deskbox-migration/任务编号 下，不自动清理。它们不进入“孤立收纳目录”列表。

空间预检要求尚需复制的数据量，另预留至少 64MiB 或数据量的 1%，取较大者。首次预检使用全量逻辑数据大小，包含文件附加流；中断副本的已有占用由当前可用空间反映。

诊断包 schema 6 加入任务编号、阶段、文件数、字节数、原文件保留标记和最近错误码；不附带文件清单、密钥或恢复密码。

## 验证

覆盖目录缺失、非空目标独有文件、空间不足、文件占用、取消并续传、源文件保持大小和时间戳但内容改变、目标篡改、目标目录失联、配置保存失败、配置提交中断、迁回保留的原位置、文件复制中取消、多个组件整批提交、创建目录阶段中断恢复，以及 1,200 个小文件的批量复制。

验证结果：

- 完整 x64 测试 4,533/4,533 通过，包含迁移安全和模块边界、source-generated JSON、语言资源占位符契约。
- 1,200 个小文件的批量复制与原文件保留测试通过；32MiB 文件复制中取消的源文件哈希保持不变。
- 独立 C→D 跨卷探针通过：64MiB 合成文件哈希一致、Zone.Identifier 附加数据流一致、空目录和源文件保留；卷序列号确认源目标为不同卷。单次记录约 894ms，不作为用户 80GB 工作负载的性能承诺。
- git diff --check 通过。
- x64 Debug 测试构建通过。常规非平台 Debug 构建与重启暂未完成：已核实 PID 35380 为本仓库标准 Debug 路径的旧实例，但 Windows 拒绝终止，待用户从托盘退出后继续。
- 简体中文、繁体中文和英文提供完整迁移提示；其他语言本批使用英文安全提示兜底，保持资源键及占位符一致。

真实 BitLocker 数据卷的锁定/解锁、物理断盘、用户 80GB 现场及风险弹窗的实际视觉验收仍待验证，合成测试不代替这些验收。

## 下一批与验收条件

1. 在独立测试卷上验证 BitLocker 解锁、迁移中锁定、重启后未解锁及解锁续传；每个中断点核对源文件哈希和最终映射。
2. 使用大量小文件及 80GB 级合成数据测量复制/校验耗时、内存及进度刷新；确认取消响应与目标空间提示。
3. 扩展 exFAT/ReFS/网络位置前，先定义数据流、权限和目录身份降级策略；无法验证的数据保留在原位置。
4. 若增加旧文件管理入口，必须作为独立功能审核与逐项校验；本批不提供自动删除或回收站清理。

## 交互与恢复补充，2026-09-29

用户实测反馈后，将弹窗改为约 520 DIP 的稳定宽度，仅跟随宿主窗口尺寸收缩。文件名与父目录各占单行，超长省略并提供完整路径提示；正文切换时保留稳定内容区域。确认界面先异步统计格子、文件与数据大小，默认只显示原文件保留、额外空间和保持连接三项重点，详细注意事项折叠显示。

复制阶段按字节计算百分比，文件数作为辅助；继续任务先显示独立的“检查已复制文件”阶段。单个文件复制后的校验仍属于复制步骤，不来回切换到最终校验步骤。停止按钮保持次要样式，原始异常放在折叠的技术详情内。

恢复前先确认原目标卷可用且卷身份一致，再核对磁盘实际状态：

- 临时区缺失时重建临时区，不丢弃已完成的副本。
- 部分目标格子目录缺失时重新预留缺失目录，并校验其他目录身份；部分文件缺失时只补复制缺失文件。
- 全部目标格子目录已移除时提供“重新开始”。明确选择后将旧记录保存在 history 子目录，再重新扫描当前源文件建立新任务，不清理任何用户目录。
- 目录被替换、卷发生变化或存在冲突内容时，提供更换位置的操作，不自动接管或覆盖。
- 磁盘未连接或未解锁时停止，不按目录已清空处理。

停止/失败状态、停止阶段、文件与字节计数、临时副本大小均持久化。配置提交状态仍保留 Committing，供启动时协调两份配置。停止不再按异常堆栈刷日志；状态页显示已知的临时空间占用，不再无条件宣称新旧副本都存在。schema 1 的旧 Copying 记录没有新增字段时，使用原目录记录中的卷身份兼容恢复。

本轮验证：完整 x64 回归 4,549 项通过；另补充旧版本恢复记录的兼容性回归。真实 BitLocker 锁定、物理断盘和实际 WinUI 视觉验收仍单独记录。
