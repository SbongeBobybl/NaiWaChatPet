# DeskBox 自启策略与验证

## 产品行为

界面保留一个“开机自启”总开关。直装版在总开关下提供“标准（推荐）”和“计划任务”选择；关闭时改选方式只保存偏好，不启用自启。商店版继续使用 Windows StartupTask，不显示方式选择。

新用户默认使用当前用户 Run 注册表项。升级时设置中的 AutoStartMode 为 null，按已有注册识别方式：已有计划任务保持计划任务，已有 Run 或旧快捷方式使用标准方式。关闭自启时保留方式偏好。

计划任务保持 InteractiveToken、LeastPrivilege、Normal 优先级、零触发延迟，允许电池供电，不等待系统空闲或网络。任务名按用户 SID 区分；XML 直接通过 Unicode COM 回读，避免进程代码页改变路径。

切换时先注册并验证新入口，再清理旧入口；清理失败回滚。计划任务注册失败时尝试标准方式，只有 Run 写入、回读及替代入口清理成功才显示回退成功，并保存 Standard 偏好，避免下次启动再次尝试计划任务。任务状态不可读取时不盲目创建第二入口。Windows 主动禁用时不自动换一种方式绕过。

旧版本迁移遵循以下规则：

| 现有状态 | 处理 |
| --- | --- |
| 没有自启注册 | 保持关闭 |
| 有已启用的本安装 Run 项 | 保留标准方式 |
| 有已启用的本安装旧快捷方式 | 注册并验证标准 Run 项，再删除旧快捷方式 |
| 旧 Run 项被 Windows 启动应用禁用 | 保留禁用决定，不迁移绕过；清理本安装的替代启动入口 |
| 计划任务或登录触发器被禁用 | 保持禁用；用户可以主动通过软件开关重新启用 |
| 指向另一有效安装的注册 | 不抢占；报告路径不匹配 |
| 迁移失败 | 保留旧入口；清理失败时回滚新任务，报告具体错误 |

关闭自启、卸载清理均保留安装路径归属检查。旧 Run 项删除后需要读回验证。替换计划任务后若验证失败，尝试恢复替换前的任务 XML。

## 两版共用的组件恢复

通知激活先订阅回调并注册通知管理器，成功后才调用 Windows App SDK 的 GetActivatedEventArgs。注册失败或进程不支持通知时跳过解码，保留普通启动。自启来源识别使用 Windows 平台的激活 API，不进入通知反序列化。

启动期通知先写入有界的类型化 envelope，再由就绪后的主实例处理；构造期注册不会在 OnLaunched 中重复销毁重建。看门狗从拿到实例锁后的构造期开始覆盖。普通第二实例不注册通知；通知第二实例注册并取得参数后继续使用已有转发队列。

组件创建仍在调用者的 WinUI 同步上下文中进行。最多同时等待两个组件的异步内容就绪，避免慢组件阻塞所有后续组件。每个组件的异常单独记录，整个恢复阶段仍等待所有组件完成后，再进行分组恢复、位置修正与层级处理。

直装版自启迁移检查放在 OnLaunched 完成后执行，与设置开关操作使用同一把锁串行化。Explorer 就绪检测、恢复快照和设置加载的顺序保持原有约束。

## 商店版计划任务验证结果

商店版继续使用清单中的 Windows StartupTask。没有将实验性计划任务接入正式商店启动入口。

2026-09-13 在本机 Windows 11 build 26200 上，用独立名称、现有可信测试证书和普通用户账号进行了 MSIX 生命周期探针：

1. 安装 1.0.0.0，通过登录任务调用清单注册的应用执行别名，成功运行，token elevated=0。
2. 原位更新到 2.0.0.0，不修改任务的启动路径，再次运行任务，成功启动新版本，token elevated=0。
3. 卸载测试包，计划任务仍然存在。
4. 测试脚本随后清理了自己创建的任务，确认包和任务均已移除。

稳定别名解决了版本目录变化，但未解决应用自行注册任务的卸载残留。因此商店版暂不以计划任务作为默认自启方式。需要一个受支持且经过验证的清理机制后，才能重新评估这项切换。

复现脚本：`scripts/Test-StoreStartupTaskLifecycle.ps1`。参数是用户证书存储中已有测试证书的 Thumbprint 和独立输出目录。脚本不安装证书；每次使用随机的包名、别名和任务名，仅清理自己创建的系统注册，保留日志及测试包。

此探针验证的是本机侧载 MSIX 的启动、更新和卸载，不等同于真实商店安装、Store flight、WinUI 组件拖拽或真实开机时序测试。

## 发布前验收

- 同一个 Release 版本，分别记录登录到进程启动、首个组件出现、组件可操作的时间，避免把 Debug 热启动当作开机提速数据。
- 验证 Windows 10/11、x64/ARM64，以及多用户、笔记本电池、Explorer 较晚启动和存储目录暂时不可用的情况。
- 检查普通权限、外部文件拖入拖出、分组切换、组件层级及关闭自启后的下一次登录行为。
- 商店版通过真实商店包验证 StartupTask 的启用、禁用、更新后保留状态；直装版确认旧 Run/快捷方式迁移后只有一个有效入口。
