# DeskBox 桌面自动整理与一键整理方案

> 状态：第三轮独立任务窗口重构已完成  
> 最后更新：2026-07-31  
> 约束：开发中如果实现与本文发生偏差，必须先更新本文并记录原因。

## 1. 目标

DeskBox 提供三条共用底层能力、风险等级不同的桌面整理流程：

1. **首次引导整理**：新用户明确确认后执行一次保守的快速整理。
2. **一键整理**：用户随时扫描、预览并确认整理当前桌面。
3. **自动整理**：默认关闭；开启后只处理基线之后新出现且满足安全条件的文件。

所有流程必须让用户在移动发生前知道：

- 桌面共发现多少项目；
- 哪些项目会被整理、哪些会被排除以及排除原因；
- 将复用或创建多少个格子；
- 每一类文件将进入哪个格子；
- 文件将被移动到哪个实际目录。

未获得明确确认时，不得移动首次扫描或一键整理中的任何文件。

## 2. 稳定身份与整理规则

整理规则不得依赖格子显示名称。名称允许用户随时修改，也可能因本地化变化。

- `WidgetId`：格子的永久身份，作为整理目标。
- `DisplayName`：仅用于展示。
- `OrganizationRule`：描述目标 `WidgetId` 接收的类别、子类型和扩展名。

格子改名、移动、加入或移出格子组时规则不变。规则始终绑定成员格子，而不是格子组宿主或当前活动成员。

目标格子删除、目录丢失或不再是文件格子时，规则进入暂停/需修复状态；不得静默改投其他格子，也不得仅凭相同名称创建替代格子。

### 2.1 规则精度

规则支持三层精度：

1. 大类：快捷方式、文档、图片、媒体、安装包与压缩文件、其他。
2. 子类型：PDF、Word、Excel、PowerPoint、音频、视频等。
3. 自定义扩展名：例如 `.rp`、`.fig`、`.dwg`。

匹配优先级：

```text
自定义扩展名
→ 具体子类型
→ 文件大类
→ Other 兜底
→ 保留在桌面
```

同一个具体类型只能有一个自动整理目标。用户把已被占用的类型分配给另一格子时，必须明确确认“从原格子接管”，然后从旧规则中移除，禁止复制或随机选择。

### 2.2 默认分类

| 稳定类别 ID | 默认内容 |
|---|---|
| `Shortcuts` | `.lnk`、`.url`、`.appref-ms` |
| `Documents` | PDF、Office、TXT、Markdown 等 |
| `Images` | JPG、PNG、WebP、SVG、HEIC、PSD 等 |
| `Media` | 视频和音频 |
| `Packages` | ZIP、7Z、RAR、ISO、EXE、MSI、MSIX 等 |
| `Other` | 未匹配的普通文件 |

默认分类只依据扩展名/系统文件类型，不依据文件名、自然语言或用户界面语言。

## 3. 扫描范围与排除

第一版只扫描当前用户真实桌面目录的顶层项目，兼容 OneDrive 重定向桌面。

默认排除：

- 公共桌面项目；
- `desktop.ini`；
- 隐藏、系统、重解析点和符号链接；
- 离线云占位文件；
- 正在下载或临时后缀；
- 正在写入、锁定或扫描期间发生变化的文件；
- 文件夹（第一版不递归整理）。

不得跟随链接或递归进入目录。

## 4. 首次整理与格子数量

首次引导增加独立的“收纳位置与桌面整理”步骤：

```text
选择并验证收纳路径
→ 只读扫描
→ 分类和目标格子预览
→ 用户确认
→ 事务执行与进度
→ 结果及撤销入口
```

默认规则：

- 每个事务最多新建 **4 个格子**；
- 优先复用已有且已绑定规则的格子；
- 项目过少的类别并入 `Other`；
- 超过四个非空类别时，最小类别依次并入 `Other`；
- 可整理项目少于 5 个时，不强烈推荐整理；
- 保存本次映射为后续一键整理规则，默认开启；
- 保存规则不等于开启自动整理。

首次整理默认排除需要长时间传输的项目。现有拖放以目录或一批文件总大小超过 10 MB 作为需要展示忙碌状态的边界；桌面整理则把单个超过 100 MB 的文件直接列为“暂不移动”，并对整个快速批次另设总量上限。

为避免极端桌面一次处理过多内容，首次和默认一键整理的快速批次最多处理 200 个文件、累计 100 MB；超过部分保留在桌面并列入“稍后处理”。挑选时优先体积较小的稳定文件。该批次上限不改变单文件 100 MB 的自动整理限制。

下载和解压属于高频文件活动：识别常见临时/控制后缀，连续事件按父目录合并，并在目录安静后再进入单文件稳定性检查。最终文件名直接写入时，稳定探测需要更长的连续静默窗口；无法确认完成的项目继续延迟，不提前移动。

## 5. 收纳路径

收纳路径必须位于扫描和确认之前；改变路径后必须重新生成目标计划。

路径验证：

- 目录可写；
- 不能是桌面自身或桌面子目录；
- 不能是系统根目录；
- 可用空间足够；
- 网络盘或移动磁盘显示额外风险说明；
- 所有目标文件名在执行前确定，禁止静默覆盖。

确认文案必须说明文件是从桌面**移动**到该目录，而不是复制。

## 6. 设置页信息架构

入口：`设置 → 文件格子 → 桌面整理`

桌面整理设置页只负责长期规则和自动整理偏好，不再承载一次性扫描、预览或执行状态：

1. 顶部状态与主要操作：面包屑已表达页面身份，不再重复页面标题和功能说明；直接展示自动整理状态、有效格子/规则数量和主操作“整理桌面…”。主操作打开独立整理任务窗口。
2. 自动整理：没有有效规则时显示“设置自动整理”，不展示一个开启后无效果的空开关；具备有效规则后才显示立即生效的开关。
3. 整理规则：默认按目标格子展示，用户看到的是“这个格子接收哪些文件类型”，内部稳定身份仍为 `WidgetId`。
4. 整理记录：最近一次整理和撤销是上下文反馈，不长期占据一张同权重卡片。

收纳路径由上一级“文件格子”设置中的“收纳与路径”统一管理。桌面整理主页不重复展示路径卡片；只有进入扫描预览和首次引导等即将移动文件的任务流程时，才再次明确展示实际目标路径。

系统托盘增加“整理桌面…”命令。托盘、设置页和首次引导必须打开同一个单实例整理任务窗口；点击任何入口都不得直接移动文件。

一键整理属于任务流而不是普通设置。扫描后使用独立任务窗口展示数量、目标格子、根路径和排除摘要，用户点击带数量的明确主按钮后才执行。复杂计划不再放入 `ContentDialog`，也不再嵌入设置页。

### 6.1 按格子

使用可搜索、可筛选的紧凑格子卡片列表。卡片展示：

- 当前图标和显示名称；
- 是否位于格子组；
- 规则摘要；
- 自动整理启用状态；
- 目标路径和失效/冲突状态。

点击卡片进入二级详情页，不在主页同时展开大量规则。

详情页支持：

- 进入详情后隐藏桌面整理主页的重复标题，使用紧凑返回按钮与格子名称/路径建立单一页面身份；
- 启用/暂停整理到该格子；
- 由一个“当前接收的文件类型”折叠区同时承担摘要和编辑入口，不重复展示标签摘要与说明区；
- 规则编辑区使用“整类文件”和“指定格式”两层用户语言，并在每一项下列出实际扩展名；整类规则是兜底范围，指定格式优先级更高；
- 未选择文件类型时禁用整理开关，并在折叠区内就地说明，不使用占据顶部的提示条；
- 自定义扩展名和排除扩展名归入高级选项；
- 类型已属于其他格子时明确展示当前目标，使用“改到此格子”语义处理接管；
- 清除规则（不删除文件和格子）。

组件优先使用 WinUI 和项目已有 Toolkit：`SettingsCard`/现有设置卡片样式、`ToggleSwitch`、`ListView`、`AutoSuggestBox`、`ItemsRepeater`、`InfoBar`、`ContentDialog`。

首次引导和一键整理预览不能只展示数量。每个目标格子至少列出若干实际文件名及“识别类型 + 扩展名”，其余数量使用紧凑汇总，避免在最多 200 个文件时一次创建过多视觉元素。

### 6.2 按文件类型

以“文件类型 → 当前目标格子”展示同一份规则，提供全局排查遗漏和冲突的视角。该视图和“按格子”编辑的是同一数据源。

### 6.3 独立整理任务窗口

独立窗口采用 Fluent 的渐进披露和单一主操作，不复刻设置页的信息密度：

- 同一时间只存在一个整理任务窗口；设置页、系统托盘和首次引导均激活这个实例。
- 窗口关闭后立即释放；下次打开重新只读扫描桌面，不缓存可能过期的整理计划。
- 窗口失去焦点时保持打开，避免用户查看桌面文件时丢失任务上下文。
- 任务显式划分为扫描、复核、执行、完成和失败五种状态；每个状态只展示当前需要的信息与操作。
- 执行期间拦截关闭操作并解释原因，直到事务完成或安全回滚结束。
- 复核状态默认每个目标格子展示 2 个实际文件名及“识别类型 + 扩展名”，其余文件通过“显示更多”逐步展开。
- 设置页继续承担规则、自动整理和历史偏好；独立窗口只承担本次扫描、确认、执行和结果。

## 7. 格子布局

新格子在主显示器工作区右上角开始布局：

- 距边缘 12–16 逻辑像素；
- 自上而下排列，满列后向左新增一列；
- 对所有可见 DeskBox 窗口/组宿主做矩形碰撞检测；
- 避开任务栏，不越出工作区；
- 不允许重叠。

执行移动前必须计算完整布局。如果空间不足，继续合并类别；仍无空间时创建一个综合整理格子或取消执行，禁止先移动后处理布局。

## 8. 事务、回滚与恢复

桌面整理是一个跨多个目标格子的原子批次：

1. 只读扫描并记录源路径、大小、修改时间和可用文件标识。
2. 生成确定性的分类、目标路径和窗口位置计划。
3. 用户确认。
4. 执行前重新验证源文件未变化。
5. 创建隐藏的临时目标目录和候选格子配置。
6. 按计划移动文件，并逐项写入磁盘恢复日志。
7. 保存规则、格子配置和一条批次历史。
8. 确认宿主可显示后，一次性呈现所有新格子。
9. 任一步失败，恢复已移动文件并移除临时配置和目录。

历史结构必须支持：

- 一个事务对应多个目标 `WidgetId`；
- 每个文件记录原路径、目标路径和目标格子；
- 整批一次撤销；
- 同名恢复冲突时使用安全可用路径并明确报告实际位置。

应用启动时检测未完成恢复日志，先恢复或引导用户恢复，不能遗留半批文件和幽灵格子。

## 9. 自动整理

自动整理默认关闭。开启时创建当前桌面基线，只观察之后新出现的文件，不追溯处理已有项目。

稳定性要求：

- 文件系统事件防抖 3–5 秒；
- 连续 2–3 次确认大小和修改时间稳定；
- 确认文件不再写入；
- 跳过目录、临时文件、云占位和需要长时间传输的项目；
- 用户正在拖动、重命名或已有整理事务时暂停；
- 全局事务串行，同一路径事件合并；
- 自动整理后提供目标格子提示和撤销；
- 没有有效目标规则时保留在桌面，不擅自创建格子。

## 10. 忙碌状态

首次快速整理由引导页承载进度。包含较大项目的日常整理复用现有导入忙碌视觉，并扩展为跨格子的全局整理会话。

忙碌期间：

- 禁止受影响文件格子的移动、重命名、刷新和重复整理；
- 不必锁定天气、音乐等无关格子；
- 取消只发生在安全检查点，随后回滚；
- 明确显示已完成数量、总数和目标根路径。
