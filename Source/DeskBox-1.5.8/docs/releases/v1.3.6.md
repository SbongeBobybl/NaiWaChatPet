# DeskBox 1.3.6

DeskBox 1.3.6 was prepared on August 4, 2026. This is a reliability and interaction release for widget groups, file importing, capsule transitions, and the follow-up desktop-organization experience.

## Highlights

### Widget groups stay responsive

- Group member content is retained in a small bounded cache while switching tabs. A rapid sequence no longer repeatedly tears down and recreates file grids, file watchers, and icon hydration work.
- Ctrl+Tab is handled at the owning window as one physical key gesture. Held-key repeats are consumed, rapid separate presses are briefly throttled, and a later request can replace an interrupted same-member transaction instead of requiring a manual tab click to recover.
- Space now reaches the selected file surface inside a group, so a running QuickLook instance behaves the same as it does in a standalone file widget.
- Compact and capsule expansion warm-up follows the actual member content. Work that is expensive during a size transition is deferred until the geometry settles.

### Correct window and icon lifecycle

- A group keeps the same temporary foreground state as standalone widgets at startup and across merge, detach, dissolve, and member-switch transitions.
- Grouped file content treats a first `shown without activation` notification as visible rather than as a real deactivation. Its initial file/icon hydration therefore completes automatically.
- The temporary icon fallback is a soft square rounded card, without the previous low-contrast dash.

### Cross-application file drops

- Browser virtual files preserve a resolved filename extension when they are copied into a standalone file widget, so imported images keep their normal preview association.
- Grouped file widgets now accept native OLE and `WM_DROPFILES` payloads forwarded by their owning surface window. This restores importing from WeChat and similar non-WinUI applications without weakening the normal file-drop checks.

### Desktop organization follow-up

- The organization preview displays the existing target widget that will actually receive a category instead of showing a misleading new target label.
- Placement no longer blocks a new target merely because the currently visible desktop appears full. It can choose a more suitable dynamic location, including a safe overlap when that is the only practical desktop location.

## Direct installer

- `DeskBox_Setup_1.3.6_x64.exe` supports most Intel and AMD Windows PCs.
- `DeskBox_Setup_1.3.6_arm64.exe` supports native Windows on ARM PCs.
- Both installers are framework-dependent. They reuse a compatible .NET 10 Runtime and Windows App Runtime 2.2 when present, and download only a missing dependency for the matching architecture.
- SHA-256 sidecar files are published with the installers on GitHub Releases.

## 中文说明

DeskBox 1.3.6 于 2026 年 8 月 4 日准备发布。本版本重点处理格子组可靠性、文件导入、胶囊过渡，以及桌面整理的后续体验问题。

### 格子组保持流畅

- 格子组成员在 Tab 切换之间保留有上限的内容缓存，不再在高频切换时反复销毁和重建文件网格、文件监听器和图标加载。
- Ctrl+Tab 在所属窗口中按一次物理按键手势处理。按住产生的重复按键会被消费，快速独立连发会短暂节流；后续请求可以替换被中断的同成员事务，不再需要手动点一次 Tab 才能恢复。
- 空格现在可以传递到格子组内选中的文件区域，已运行 QuickLook 时的行为与独立文件格子一致。
- 紧凑/胶囊展开预热会跟随实际切入的成员内容，尺寸过渡期间较重的工作会延后到几何状态稳定后执行。

### 窗口层级与图标生命周期正确

- 启动、合并、拆分、解散和成员切换期间，格子组会保持与独立格子一致的临时前景层级。
- 格子组文件页第一次以“显示但不激活”方式出现时，会被视为可见而非真正失活，因此文件和图标的首次后台加载可以自动完成。
- 图标加载中的临时占位替换为柔和的正方形圆角卡片，并移除原先低对比度短横。

### 跨应用文件拖入

- 浏览器虚拟文件复制到独立文件格子时会保留解析出的文件扩展名，导入后的图片可以正常按关联类型预览。
- 格子组内的文件格子现在可以接收所属表面窗口转发的原生 OLE 和 `WM_DROPFILES` 载荷，恢复微信等非 WinUI 应用的拖入，同时保留常规文件拖放检查。

### 桌面整理后续优化

- 整理预览会展示实际接收该分类的已有目标格子，而不会错误显示为新建目标。
- 当可见桌面看起来已满时，不再一律禁止新建目标；系统会继续寻找合适的动态位置，必要时允许安全重叠。
