# DeskBox 1.5.7

DeskBox 1.5.7 is a reliability and polish release. Exiting from the tray now always ends the process — on machines where the system's application-exit handshake stalls (typically Windows with UAC fully disabled and an elevated Explorer), a background DeskBox process used to survive "exit": the tray vanished and a restart worked, but the leftover process slowly ate memory and kept the right-click menu proxy alive beside it; every shutdown path now carries a delayed hard-exit backstop, and the elevation notice and search popup close along with shutdown. Windows 10 gets its drag-and-drop settings card back: the "when dragging out of a widget" card in Settings → File widgets lost its title and question-mark tip there, with its Windows 10 explanation stretching the card out of shape or spilling outside it on scaled, narrower windows — the explanation now renders in the card's description area, and long helper texts in other settings cards (cloud-backup path hint, runtime-health detail, backup summaries) are width-capped the same way. Dialogs and preview cards follow the app's theme override again: the desktop-organization abandon dialog, its preview cards, and the hotkey recorder had been picking up the raw system theme whenever the app's theme override disagreed with it, and desktop-organization rule rows both rebuild on theme flips and respond to clicks again (a leftover chevron and a click-swallowing guard shipped together in 1.5.6). Store packaging completes its 1.5.6 follow-up: the display-name resource consistently resolves to the reserved store name.

Release date: 2026-10-13 (content prepared from the `main` working tree following `fc9c2f49` — the 1.5.6 release commit — including the exit-backstop batch fixing the tray-exit residual process (feedback 555/556), the Windows 10 drag-out card layout fix, the neutral-interaction theme-scope batch, the desktop-organization rule-row click fix, and the store display-name resource follow-up).

## Highlights

- **Exit reliability (feedback 555/556).** Quitting from the tray ends the process on every machine. The shutdown sequence already released the single-instance lock and closed the tray, but its final `Application.Exit()` step only *requests* the XAML message loop to stop — where a foreign thread outlives it, the process parked as a silent zombie: no logs, tray gone, lock free, but resident and pinning the thumbnail proxy's stdin pipe (so the right-click menu proxy survived beside it, and together they could eat most of a machine's memory). Every shutdown path — graceful and deadline alike — now arms a delayed hard exit; a healthy exit outruns the timer and nothing changes, and the shutdown sequence also closes the elevation notice and the search popup, which were missing from its window list. Verified against the diagnostic packages from both reports: the same machine cycled exit/restart five times with the residual process observed each time.
- **Windows 10: the drag-out card keeps its title.** The card under Settings → File widgets → drag-and-drop behavior places its content in an auto-sized column beside the title; the Windows 10-only explanation text placed there consumed the whole column width, pushing the title (and its question-mark tip) to zero width on every Windows 10 machine, and — after a first width-cap attempt — still overflowed the card on high-scale, narrower windows because the three-column card grid does not clip overflowing columns. The explanation now appends to the card's description under the title, where it wraps within the card at any width and scale; Windows 11 descriptions are unchanged. Long auxiliary texts in four other horizontal cards are width-capped defensively.
- **Dialogs follow the app theme again.** Code-built surfaces that resolve theme brushes through application-scope lookups were following the *system* theme whenever the app's theme override disagreed with it: the desktop-organization abandon dialog showed wrong-colored secondary text, its preview cards picked up wrong surfaces and strokes, and the hotkey recorder dialog did the same. They now resolve against their own window-scoped theme with a neutral fallback, and the desktop-organization rule rows rebuild their brushes when the applied theme flips.
- **Rule rows click again.** The 1.5.6 code-built settings-card conversion of desktop-organization rule rows shipped two regressions at once: a leftover manual chevron rendered double arrows, and an over-eager `is not Button` guard swallowed every row click. Both are gone, pinned by a contract test.

## 中文说明

DeskBox 1.5.7 是可靠性与打磨版本：从托盘退出后进程必定结束；Windows 10 的"拖出格子时"设置卡片恢复标题与问号提示、说明文字不再撑坏卡片；对话框与预览卡重新跟随应用主题；桌面整理规则行恢复可点击；商店包显示名资源完成 1.5.6 收尾。

### 主要更新

- **退出可靠性（反馈 555/556）。** 此前在某些机器上（典型为 UAC 完全关闭且资源管理器以管理员运行的 Windows），托盘退出后退出流程本身走完——托盘消失、单实例锁释放、再次启动正常——但最后一步"应用退出"请求未能真正结束进程：残留进程驻留后台、慢慢吃内存，还握着右键菜单代理的管道让代理一起驻留（两份诊断包显示用户反复退出/重启五次均复现，两个进程合计吃到七成内存）。现在所有退出路径都布置了延迟强制结束的保底：健康退出时定时器来不及触发、行为不变；退出序列同时补关此前漏出清单的提权提示窗与搜索弹窗。直装版与商店版同享此修复。
- **Windows 10：拖出卡片保住标题。** 「设置 → 文件格子 → 文件拖放行为 → 拖出格子时」卡片的 Windows 10 专属说明文字此前放在标题右侧的内容列里：无宽度约束时整列被吃满、标题（连同问号提示）被挤到零宽；加了宽度上限后在高缩放、较窄窗口下仍会因卡片网格不裁剪溢出列而画出边界。现在说明文字拼接到卡片标题下方的描述区，任意窗口宽度与缩放下都在卡片内换行；Windows 11 的描述不变。其余四张横向卡里的长辅助文字（云备份远端路径提示、运行时健康详情、备份摘要等）同样限宽防御。
- **对话框跟随应用主题。** 桌面整理的放弃确认对话框、预览卡、热键录制弹窗此前经应用级资源查找取主题画刷，在应用主题覆盖与系统主题不一致时颜色取错；现改为按各自窗口范围的主题解析并带中性回退，桌面整理规则行也会在主题切换时重建配色。
- **规则行恢复可点击。** 1.5.6 的代码行转换同时带入了残留箭头（双箭头）与吞掉整行点击的守卫，均已修复并由契约测试钉住。
- **商店包。** 显示名资源统一解析到保留名（DeskBox Widgets），完成 1.5.6 打包收尾；直装版不受影响。
